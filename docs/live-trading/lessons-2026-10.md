# Lessons from the Boost dry run (2026-10)

The lessons the Boost dry-run week (2026-10-24 to 10-28) taught, which every momentum slice must build in and which code comments and tickets cite by number (for example `docs/live-trading/lessons-2026-10.md` L7). The table is copied verbatim from the owner-approved Momentum paper plan of 2026-10-28.

| # | Boost lesson | Where it came from | What momentum must do |
|---|---|---|---|
| L1 | Loading every instrument of every session killed the 2 GB server (OOM, twice). | #583/#584 | Rank one session at a time within a stated memory budget (#585), tested with data shaped like real recordings (thousands of names, two years). Measure the server total with three engines before the IRAs go live. |
| L2 | The free Massive plan serves a session only the next morning; evening data jobs got 403. | #592/#593 | The IRA decision happens on the first session of the month from the previous session's closes, so the morning data path is fine; but the universe snapshot and the ranked histories must also arrive in the morning, before the 09:00 cutoff, and the month-end session may be a holiday (calendar input, already handled). |
| L3 | A morning account reading counts as the close only with the Flex trade-confirmation proof; IBKR fixes the Flex period at "Today", so the reader sends dates. | #595/#596, ADR 0019 | Each IRA gets its own Flex reader instance, staggered (trad-ira 05:45/06:45/07:45, roth-ira 06:00/07:00/08:00) because one token is shared and IBKR paces requests. The morning reading rule applies to IRA decisions too. |
| L4 | The Gateway's nightly restart (23:45 ET) can fail login and sit on a dialog for hours; only an adapter alert exposed it. | #590 | Build #590 (logged-out alert + retry) before the IRAs, since three adapters will depend on one Gateway. |
| L5 | ibapi hands the connection time as bytes; IBKR labels it "EST" all year; the test fakes returned what we expected, not what IBKR sends. | #597/#598 | Adapter fakes are built from captured real formats (synthetic values, real shapes). A post-install probe runs on the real server after every adapter install. |
| L6 | IB Gateway 10.50 never frees account-summary slots; balances had to come from reqAccountUpdates. | #589 | The IRA adapter instances reuse the Boost adapter unchanged; one adapter per account, each with its own client id. |
| L7 | `provision.sh services` copied the shipped boost.config back over the server's (account "joint"). | 2026-10-25 | Per-account configuration lives outside the repo copy; provisioning never overwrites it. Three config files (boost, trad-ira, roth-ira), each naming its account out of the public repo. |
| L8 | Starting a timer is not enabling it; a unit failure with no OnFailure pages nobody; Healthchecks goes DOWN while any trading unit is failed. | 2026-10-28 | Every IRA unit (engine, adapter, flex, data) is enabled, has OnFailure paging, and the reporter's unit list covers all three accounts. |
| L9 | The reporter summary assumes one instrument (SPY shadow, "Holdings: none"); v4 snapshots and v5 fills count as rejected inputs. | #460, dashboard | Reporter and dashboard read the IRA's versions and show a 25-name book plus the bond sleeve. |
| L10 | Every server bug surfaced one per morning; fixes got one real test a day. | 2026-10-27/28 | Each IRA slice ends with a same-day probe on the real server, not a wait for the next morning. |
| L11 | A withheld decision looks like a quiet success unless someone reads the summary. | 10-26, 10-27 | A withheld IRA rebalance pages (#380), since it skips a whole month, not a day. |
| L12 | The paper account id leaks easily (screenshots, tool output). | 2026-10-25/28 | IRA paper account ids go only in the server's config; masking patterns cover DU plus letters. |
