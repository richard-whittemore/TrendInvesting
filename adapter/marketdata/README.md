# Market-data step

Fetches Massive market data once and records it as the input each engine reads (ADR 0026, section 8). Standard library only.

    python3 -m marketdata universe --out DIR            # grouped bars + type-CS tickers for the last session
    python3 -m marketdata bars --out DIR --instruments SPY,IEF,SHY

Run from `adapter/`.

- **Key:** `MASSIVE_API_KEY` in the environment, else `--secrets-file` (server, mode 600, outside the repository), else the Mac Keychain item `MASSIVE_API_KEY`. Sent only as a bearer header, and only to `https://api.massive.com`: a redirect anywhere else is refused, so the header is never forwarded; never logged, cached or written.
- **Session:** `--asof` defaults to today's New York date (not the host's). The session is the latest NYSE trading day on or before it, from the committed calendar (`nyse_calendar.py`), never from an empty response. It is refused until its close (4 p.m. New York, 1 p.m. on an early close) plus `--settle-minutes` (default 60), so intraday bars are never recorded as a close.
- **Fail closed:** a session not yet settled, an empty response on a trading day, an empty ticker list, a missing instrument bar, a repeated pagination cursor, or a repeated 429 raises and writes nothing; the CLI exits 1 for the caller to alert on.
- **Recording:** `DIR/<kind>_<session>.json` holds the raw rows, source, fetch time and a SHA-256; never overwritten. Installed by hard link, then the directory (and the parent of any directory created) is synced (ADR 0018); a failed sync reports that the file is recorded.
- **Daily bars:** Massive, three requests per instrument (raw, split-adjusted, dividends); at 5 requests a minute that is about 40 seconds an instrument.
- **History (one-time backfill, resumable):** `python3 -m marketdata backfill --out DIR --sessions 253` records one grouped (all US stocks, unadjusted) request per session, about 53 minutes at 5 a minute; existing recordings are skipped, never overwritten. Closed days come from the committed NYSE calendar (`nyse_calendar.py`), never from an empty response: an empty response on a trading day fails with nothing recorded and is retried next run; a trading day with no recording is a gap and fails the read. `python3 -m marketdata actions --out DIR --lookback-days 400` records the bulk splits and dividends for the window; a window with only one kind recorded resumes with the other. Both commands honour the settle delay. `history.load_actions(DIR, kind, first, last)` counts an action in overlapping windows once (by Massive's `id`), refuses two different copies of one action, and fails with a gap unless the recorded windows cover first..last.
- **Adjusted closes:** `adjust.adjusted_closes` derives them from the recorded raw bars and actions; the convention (backward ratio, as QuantConnect's Adjusted mode, including a dividend on a split date) is stated in `adjust.py`; non-finite or non-positive inputs fail closed.
- Ranking is a Go rule and is not done here.
- **Sectors:** `python3 -m marketdata sectors --out DIR` records iShares' IWV holdings file (GICS) and Nasdaq's screener (no key for either) for the latest settled session only (fetched after its close plus the settle delay and before the next close; a past session is refused, and the encoder refuses labels fetched outside that window); a rerun fetches only the source not yet recorded. Labels are GICS where IWV lists a stock, else Nasdaq's, both mapped by name onto Morningstar's eleven sectors so the cap counts one vocabulary (`sectors.py`; plan.md section 4). Every redirect hop must stay on HTTPS on the two sources' hosts (as the Massive client's redirects must stay on Massive), and each recording names the URL its body was read from.
- **Engine inputs (no network):** `python3 -m marketdata encode --out DIR --first YYYY-MM-DD --asof YYYY-MM-DD --instruments SPY,IEF --optional ... [--universe-members] [--base YYYY-MM-DD] [--engine momentum|boost] --configuration-hash H --strategy-version V --run-id R --stream FILE` reads only the recordings and writes a new file of envelopes, one per line: a `market.session.calendar` v1 reaching one session past the last, then per session each instrument's `market.bar.completed` v2 (raw, split-adjusted, and split- and dividend-adjusted, adjusted forward from the base so no bar is ever restated), the `market.universe.snapshot` v1 where a universe was recorded, and a `market.session.closed`; `--engine boost` writes only its one instrument's bars and the closes, since Boost refuses the calendar and the snapshot. The file is installed by hard link from a synced temporary file, so a failed run leaves nothing to block the retry. Keep `--base` fixed for an engine's journal: bars on two bases are refused. With `--universe-members`, a stock written only as a member with a malformed bar (including a missing or negative close or volume in the universe recording) or a split or dividend that cannot be adjusted exactly is left out of only that session for a bad bar, or of only the first session on or after the ex-date for an unadjustable action (the prices on each side of the jump keep their true returns). The momentum rule's own 253-close window then keeps it out of every ranking that reaches the left-out session, so no complete window spans the jump, and it is ranked again when its window is complete under that rule (ADR 0026 point 5). In both cases there is no bar and no mention in the session close. It is named on stderr with the sessions (`excluded TICKER from FIRST to LAST (N sessions): reason`); a member left out of a session for bad data, and a universe snapshot row with a missing or negative close or volume, is left out of that session's snapshot too, whichever stream is written, so the snapshot records it and a momentum engine configured `"bars"` can require a bar for every stock it ranks. SPY, IEF, SHY and the other members are still written; bad data in a `--instruments` or `--optional` instrument still refuses the stream. The convention and every fail-closed case are in `encode.py`; `tests/testdata/envelope_contract.go` checks the output against the Go validators.
- **Universe input shape:** the momentum configuration declares the shape of its stream in `momentum.universe_input` (from configuration version 6): `"bars"` for a stream written with `--universe-members`, `"compact"` for one written with `--ranker`; the engine refuses a configuration without it and never infers the shape. `encode` with neither flag writes a bars stream with bars only for `--instruments` and `--optional`, so most ranked members have no bar and a momentum engine withholds every month's decision from it (`missing-bars` configured `"bars"`, since every ranked member needs its bar even when the names held rank; `histories-missing` configured `"compact"`).
- **Compact universe stream:** `encode ... --ranker "bin/universe-rank -config momentum.json"` (a configuration declaring `"universe_input": "compact"`; `universe-rank` refuses `"bars"`) writes bars only for `--instruments` and `--optional`, the universe snapshot per session, and at each decision session one `market.close.history` v1 per member the Go ranker (`cmd/universe-rank`, the engine's own rule) names, with the adjusted closes its bars would carry over the window; the calendar starts at `--base`. Nothing ranks in Python, and the engine re-ranks and refuses a different set (`docs/manual/momentum-universe.md`).
- **Cancelled sessions:** `python3 -m marketdata retract --out DIR --session YYYY-MM-DD --reason TEXT` records once (no key) that the exchange cancelled a session; `encode` writes it as `market.session.retracted` v1 right after the calendar and treats the day as no session (no recording needed; one with bars recorded is refused).
